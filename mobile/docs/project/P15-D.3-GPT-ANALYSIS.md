## 2. Onde o GPT ERROU e DISCORDO (Provado via Código)

### Erro 1: "A montagem do AlertsDrawer está comentada"
O GPT afirmou que o componente \AlertsDrawer\ (dentro de \TopHUD.tsx\) também assina o \useGameState\, mas presumiu que ele estaria comentado (\{/* <AlertsDrawer ... /> */}\) no snapshot, invalidando-o como variável.
**Isso é factualmente incorreto.** 
No código do snapshot (\src/ui/components/TopHUD.tsx\, linha 461), a montagem está ATIVA:
\\\	sx
<AlertsDrawer       visible={alertsVisible}      onClose={() => setAlertsVisible(false)} />
\\\
**Porém, o GPT errou na mecânica do React:** O fato do \AlertsDrawer\ ser um consumidor do Context e estar ativo não afeta em absolutamente NADA o número de renders do pai (\TopHUD\). No React, quando um filho atualiza via Context, a renderização começa nele, sem forçar o pai a renderizar. Portanto, a assinatura de Context do \AlertsDrawer\ é isolada e irrelevante para a métrica \	opHudRenders\.

### Erro 2: A Causalidade Total (O Context não explicava a duplicação)
O GPT pontuou como "comprovado" que remover a assinatura direta do TopHUD não diminuiu os renders, logo a assinatura não era suficiente para explicar os renders extras. 
A verdade é: **ela explicava, mas o TopHUD recebia atualizações redundantes**. 
Antes da nossa intervenção, quando o \GameContext\ era atualizado:
1. \AppContent\ (consumidor) disparava cascata para \TopHUD\.
2. \TopHUD\ (consumidor direto antes da remoção) recebia também o mesmo update de Context.
O React agrupa (batcheia) atualizações de Context do mesmo ciclo. Remover a assinatura do TopHUD *parece* não ter feito efeito, mas na verdade apenas eliminou um caminho de dupla-sinalização redundante, deixando a rota da cascata visível.
