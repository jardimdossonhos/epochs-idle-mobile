# P15-C.2-CORRECTED-COMPARATIVE-AUDIT

## 1. Escopo
Esta é uma auditoria formal quantitativa e observacional que substitui o relatório C2 anterior. O objetivo é analisar os dados brutos da execução física C2 Corrigido, validando a integridade da série temporal e comparando empiricamente os resultados com as baselines B2 e B3, distinguindo estritamente observações de conclusões causais.

## 5. Auditoria de Parsing
A inicialização de VmRSS/RssAnon etc com "0" no script não contaminou os dados, pois as 31 amostras extraíram valores >0 do run-as. O run-as funcionou em 100% dos ciclos. Nenhum fallback indevido deturpou a contabilidade real. As colunas Views e ViewRootImpl foram coletadas, resultando em 0 e 1 constantes, o que reflete limitação do dumpsys nesse ambiente de shell, e não zeramento de fallback por erro.

## 10. GC
- SAWTOOTH_OBSERVED: Crescimento do PSS 631MB(T0) -> 666MB(T240). 
- Queda abrupta no T260 (655MB).
- Logcat confirma: \12:53:25.514 Background young concurrent mark compact GC freed 6852KB\ (ocorre exatamente entre T240 e T260).
- Vale pós-GC (T260) é de 655MB. Isso representa um ganho de +24MB (retenção residual temporal) sobre a baseline local inicial (T0=631MB). 
- PERSISTENT_RETENTION_SUGGESTED pelos dados numéricos. Não se afirma "memory leak".

## 17. Hipótese dos Modals
- B2: TopHUD + Modals apresentou crescimento residual de PSS.
- C2: TopHUD SEM Modals também apresentou crescimento residual de PSS (Vale +24MB).
- Os dados NÃO sustentam a hipótese de que a presença dos seis Modals seja condição necessária para o crescimento observado.

## 18. Hipótese TopHUD
- B3 (sem TopHUD) = retenção residual estável.
- C2 (com TopHUD isolado) = retenção residual ascendente.
- Os dados demonstram que TopHUD é a causa do crescimento? NÃO PROVADO.
- Os dados, no entanto, correlacionam temporalmente e estruturalmente o retorno do padrão Sawtooth residual com a restauração do TopHUD e de sua métrica constante de alta frequência de re-renders.

## 19. Hipótese Engine
- C2 manteve Game Loop (ticks=30) e providerUpdates. Não exclui a influência inerente aos arrays ECS base no NativeHeap/Unknown em fluxos intensivos de updates na bridge, indicando que o fenômeno se reproduz desde que a UI ouça os dados da tick-pipe, mesmo cortando renderização de camadas (Modals).

## 20. O que os dados PROVAM
- Provam que C2 executou 31 amostras T0-T300 sem oscilar o PID e mantendo map/canvas zerados.
- Provam que TOTAL_PSS elevou e a porção residual pós-GC (T260) permaneceu distante do T0 (retenção).
- Provam que o crescimento se concentra principalmente sob o marcador Unknown.
- Provam empiricamente (B2/C2) que os seis Modals filhos não são o gatilho solitário ou condição estrutural dependente para que essa retenção residual apareça.

## 21. O que os dados NÃO PROVAM
- Não provam se JSI, Hermes ou Fabric são "os culpados".
- Não provam que há memory leak irrecuperável a longo prazo (apenas retenção progressiva local no frame temporal de 300s).
- Não ditam uma solução específica de React.memo ou useCallback.

## 22. Limitações
- Teste C2 correu sob bundle --dev false contrastando com B2 --dev true.
- O dumpsys Android não decompõe a classe "Unknown" sem intervenção nativa de profiling C++ ou heapdumps profundos da engine.
